## 对原计划的核查与调整

四个方位、两个外伸量、三个瞄准区的粗筛思路合理；要固定轨迹、分阶段评价，不能只看张手或全程平均。

1. DexUMI §3.2 确认了腕下 150° **对角视场角**相机，并针对 XHand/Inspire 的系统保持训练和部署外参一致。它不是 Revo3 位置最优性证据，也不是45°安装依据。[原论文](https://arxiv.org/html/2505.21864v1#S3.SS2)；[硬件](https://dex-umi.github.io/tutorial/hardware.html)。
2. Revo3 官方资料给出21主动自由度，拇指5、其余每指4。实际模型需对照关节和传感器版本验收。[官方参数](https://www.brainco-hz.com/docs/revolimb-hand/revo3/parameters.html)。
3. 《Eyes on the Prize》是 arXiv:2204.13879 **v1**，最新版标题改为 DGBench，并非原引用指向无关工作。使用版本链接锁定引用；多相机抓取研究不能替代 Revo3 单相机三任务验证。[v1](https://arxiv.org/abs/2204.13879v1)。
4. 官方模型仓库提供左右手的 MJCF/URDF，可作为待选资源，不自动选作你的正式模型。官方也注明控制器增益和任务配置由下游补充；导入成功不等于具备可靠动态操作能力。[官方模型](https://github.com/BrainCoTech/brainco-description)。
5. 20/40 mm 应定义为从**已测量的零外伸光心**沿支架外伸方向增加的距离；若从外壳表面测量，必须再乘上外壳到光心的变换。不是直接把光心设置在腕原点20/40 mm处。

## 软件现在能做什么

- 原有 MJCF/URDF 导入、多相机显示、相机父 link 挂载、静态/动态、项目保存保留。
- 新增 `lab.scene.attach(path, parent=..., position=..., rotation=...)`：将固定根手模型挂在真实腕 link 下，参数为父坐标系米制位置和 wxyz 四元数。普通 Append 放在 world，不能代替装到机械臂上。
- 新增 `lab.state()`：复制关节名称、qpos 地址/长度、限位和当前 qpos/qvel。
- 新增 `lab.seek(qpos=..., time_s=..., qvel=...)`：完整状态运动学回放，不推进动力学，暂停仿真并使旧控制失效。每次 seek 创建新 run，step_index=0；样本序号由实验CSV另存。不是机器人控制命令。
- 新增表面关键点几何评测、24候选生成器、逐帧 CSV / 分阶段 JSON / 最差样本 RGB+深度 NPZ。
- 使用 Python 实验入口，无需新增专用桌面向导。可在桌面编辑/检查相同模型，实验脚本负责批量重复比较。

当前批量回放支持模型 qpos/qvel 控制的身体；mocap 物体尚不支持逐样本设置，应在评测模型里用 free joint 表达需要回放的物体。完整 qpos 必须包含物体位姿，不能只存手关节。

## 阶段 A：整机模型与坐标验收

1. 选择正式机械臂和右手模型，记录源仓库commit、网格与模型文件哈希、单位。保留视觉网格和固定 wrist/palm links。
2. 单独打开机械臂、手；逐关节检查名称、方向、限位、零位。不要把21个SDK电机编号直接当成MuJoCo qpos顺序，使用 `lab.state()['joints']` 建映射。
3. 确定 `T_wrist_hand` 后使用 attach。子手根不能包含 free joint；根已固定的手仍保留内部21个关节。URDF传动不会自动生成MuJoCo执行器。
4. 完整整机优先保存成经过核对的MJCF，记录关节映射。动态阶段另校验质量、惯量、摩擦、接触、执行器/耦合与控制器。
5. 相机外参定义 `T_wrist_camera`，光学轴为x右、y下、z前。将相机配置为腕link子节点，固定安装，不能使用持续自动看向目标的 tracking 相机冒充固定安装。
6. 回放转腕±20°（在整机限位内），验证相机随腕运动且 `inv(T_world_wrist) @ T_world_camera` 恒定；桌面同时看全局视角和一路输出。

```python
from camera_lab import CameraLab

# 路径、link和变换必须用实际值替换。
with CameraLab(model=ARM_PATH) as lab:
    lab.scene.attach(HAND_PATH, parent=WRIST_LINK,
                     position=HAND_TRANSLATION_M, rotation=HAND_QUAT_WXYZ)
    print(lab.state()['joints'])
    print(lab.cameras.describe())
    lab.save_project(PROJECT_PATH)
```

本实验CLI的model入口目前读取MJCF/URDF，不读取camproj；已有camproj可通过SDK load_project检查或另写SDK调用脚本。不要把ZIP项目当成XML传给CLI。

## 阶段 B：为三个任务采集同一批状态序列

每类先准备 **3条代表序列**，每条覆盖完整操作阶段；这是建议起步数量，不是统计充分性声明。

| 任务 | 必须包含的阶段 | 标注的表面关键特征 |
|---|---|---|
| 抓取/放置 | 接近、对指、闭合、抬起、移动、放下、释放 | 抓取特征、接触附近指尖表面、落点边缘 |
| 手内操作 | 拇指对掌、旋转、换指、重新稳定 | 物体朝向标记、参与换指的指尖附近表面 |
| 精细装配 | 接近、末端对准、插入开始、插入、退出 | 插入件尖端邻域、孔口边缘，必须共同可见 |

记录30 Hz的时间戳、完整qpos、可选qvel与阶段标签。位姿来自仿真状态或经过对齐的实录轨迹；切勿把随机关节动作宣称为成功抓取/装配。用仿真真值回放物体运动是第一轮可见性实验的控制变量，不是闭环算法输入。

每帧显式提供 `duration_s`，例如1/30，统计时按持续时间加权。最后一帧也必须提供有效区间；不能凭空加上长尾。采样间隙不当作已知可见/不可见。短于33.3 ms的遮挡不能凭30 Hz排除，精细阶段可另用60/120 Hz离线采样复查。

**关键点必须落在可见表面**，不能使用物体中心代替表面。孔口用边缘多个点，不用孔中心空气中的点。每个关键区域取多个点，点的直径表示特征物理尺度；当前工具测的是采样点可见性，不是整片区域的可见面积。

## 阶段 C：24候选粗筛

1. 在右手腕坐标中手工确认掌侧、拇指侧、小指侧、背侧。右手标签不能靠左右手镜像或URDF轴名猜测。
2. 为四方位分别测量零外伸光心 `origin` 和支架外伸单位方向 `outward`。
3. 每个方位增加20/40 mm两个试验外伸量，先核对外壳与支架包络。若机械上不可行，记录剔除原因并替换实测可行值。
4. 在腕坐标定义三个代表瞄准区：捏持区、掌前操作区、装配区。以参考手型计算一次姿态，之后整个动作保持刚性安装。`up`显式指定，固定画面滚转。
5. 使用 `generate_candidates` 得到24个单相机布局，每次只改变相机外参，其余状态、光照、分辨率、K、任务样本完全相同。不是同时安装24个相机。
6. 分别运行9条轨迹，保存24×9份候选/轨迹指标；不只把三个任务拼接后求一次平均。较复杂场景可先低分辨率排除明显盲区，但最终像素筛选必须回到真实输出尺寸。

```python
from camera_lab.experiments.layouts import generate_candidates
candidates = generate_candidates(
    camera=CAMERA_NAME, parent=WRIST_LINK,
    mounts=MEASURED_MOUNTS,       # 每项有origin/outward，均为腕坐标
    targets=MEASURED_TARGETS,     # 三个腕坐标代表点
    extensions=(0.02, 0.04), up=IMAGE_UP_IN_WRIST)
```

不要用150°对角视场角直接填 `fovy`。实际鱼眼镜头需畸变模型或多视角采样后重投影；当前针孔评测不足以验证该镜头。可以先对去畸变后的有效针孔区域做保守测试，但结果只适用于那个裁剪模式。

## 阶段 D：指标、硬约束与角度细筛

工具逐点区分 `visible / occluded / out_of_frame / behind_camera / out_of_range / too_small / invalid_depth / surface_mismatch`。其中surface_mismatch提示标注点与渲染表面未对齐或采样误差，应检查网格/表面点，不能简单算成算法失效。

逐阶段比较：
- 各特征时间加权可见比例；全部指定特征共同可见比例。
- 每个特征及共同可见条件的最长连续失视，边界采用显式采样区间。
- 近距限制、出框和遮挡的逐帧原因；物理直径对应的近似投影像素。

**建议起步门槛，须按任务修订：** 关键阶段共同可见率≥95%，最长共同失视≤0.1 s，装配关键特征投影尺度≥8 px。以上不是论文结论，也不是“过了就能装配成功”；应记录阈值敏感性（例如4/8/12 px、0.067/0.1/0.2 s）再决策。

先排除相机/支架碰撞或安装不可行、真实近距无法成像的方案。这两项目前是**待验证**，软件未建外壳或未知道镜头参数时不能自动判定通过。需要添加真实相机/支架碰撞几何，按预先定义的禁止接触对检查机械臂、手、台面与物体全轨迹。还需裕量检查，不只看离散帧接触。

几何硬门槛通过后，用三个任务中**最低的关键阶段共同可见率**排序，另列最长失视作约束，不用不透明加权总分掩盖短板。对候选前三，在固定光心下做 yaw/pitch 各 -10°/0°/+10° 的9点邻域（共27布局）细筛。此处的旋转轴与参考姿态需写进配置，不能混淆欧拉角顺序。

当前只允许一台相机；若所有布局都不达标，应输出“单相机约束下无合格方案”，再尝试动作/握持方式调整或协商约束。不要暗自增加第二台相机。

## 阶段 E：真实光学与闭环验证

相机型号确认后补录：工作距离、焦距/分辨率模式、畸变、最近对焦、曝光与帧率、外壳尺寸/质量/出线方向；RGB-D再录最近有效距离、深度与RGB对齐方式。`min_range_m/max_range_m` 在当前工具中指相机到特征的欧氏距离；真实器件规格若按轴向距离定义，需要换算或扩展传感器模型，不能直接套用。

理想深度valid_mask仅用于几何可见性。它不模拟黑色/反光/透明材质、主动光干扰、纹理不足、双目遮挡、运动模糊、对焦失败；不能称为真实有效深度比例。近似像素尺度不是锐度或真实特征分割面积。

前三布局在固定曝光/光照和相同物体分布下实测。真实算法使用已实现的PoseEstimator适配接口，误差对比仍采用同帧、同坐标真值；加入跟踪丢失和延迟。三类任务各先做不少于20次试运行作为初筛，报告成功/总数及不确定性；不把20次称为可靠性认证。

控制策略比较保持策略版本、训练数据与训练预算一致；视角改变导致的分布变化应单独报告。动态仿真需要校准接触/摩擦和执行器，几何回放结果不能推出抓取成功率或装配精度。

## 立即可运行的软件验证

真实配置模板为 `examples/wrist/revo3-right-template.json`，未确认字段刻意留空，未填写运行会报错。

先运行随软件提供的**合成遮挡测试场景**；它不是Revo3，也不是机械臂任务验证：

```bash
cd /home/book/Projects/camera-lab
PYTHONPATH=src python3 examples/wrist/make_synthetic.py
MUJOCO_GL=egl PYTHONPATH=src python3 -m camera_lab.experiments.wrist \
  examples/wrist/synthetic.json --output reports/my-wrist-screening
```

输出目录必须不存在，避免覆盖已有实验。生成24个候选，每个9个状态样本，每个2个表面点，共432条特征记录；状态间隔1/30 s。演示没有真实相机、支架或任务成功定义，只检查软件能否区分已知遮挡。

产物：
- `config.json`：完整输入及候选外参/状态/阈值；`summary.json`：配置与顶层模型/自包含项目哈希、运行环境、限制声明、每候选分阶段指标。

- `*-worst.npz`：该候选第一个最低可见点数样本，包含RGB、理想深度、K、相机世界外参及样本索引。它不一定对应最长连续失视段，须结合CSV复查。

工具额外保存 `input.camproj`，其中归档编译后的模型和依赖网格/纹理，并记录整个项目哈希；可用桌面 Open project 或 SDK load_project 复查。顶层XML哈希本身不代表整个资产树内容相同，正式实验仍建议记录源仓库版本。
